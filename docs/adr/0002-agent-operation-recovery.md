# 0002: 操作エラーの復旧判断をAgentへ委譲する

## 状態

採用。

## 背景

実行基盤がエラー種別ごとに修復可否を判断すると、未知の修復可能な失敗でRole全体が停止する。一方、Agentによる無制限の試行や、通信断後の成否不明操作の再送は消費と整合性の問題になる。

## 決定

復旧Agentが原因を調査し、保存済み操作の再試行・通常Roleへの修正依頼・Taskの保留を選ぶ。Pythonは操作実行・記録・照合・所有と権限の検証・予算制限を担い、診断結果で保護チェックを無効化しない。

復旧の回数と経過時間を永続化し、進展なしや予算超過ではTaskを保留する。Roleは他のTaskを続行する。成否不明の操作は既存resource・SHA・requestIdで照合し、確認できない作成要求は再送しない。

## 帰結

未知のエラーもAgentが診断できる。基盤の保守権限は製品Roleへ自動付与せず、保守が必要なら記録を保持して引き継ぐ。復旧には有限のAgent消費が発生し、厳密なToken・料金の制限は別の予算管理を要する。実行境界を確保できない構成・所有の不正は停止する。
