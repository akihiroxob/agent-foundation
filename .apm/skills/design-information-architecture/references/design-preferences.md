# デザインの既定の好み

この共有パッケージの利用者が明示した主観的な好みを、次の画面・Projectの初期案でも参照するための資料。一般原則の実証や、他の利用者への強制ではない。利用者・Projectの最新の明示方針、内容の理解、操作上の必要性に合わせて適用する。製品名・業務Entity・ページ名・固定の寸法は対象製品の資料で管理する。

| 好み | 初期案への反映 | 適用上の区別 |
| --- | --- | --- |
| 大きな枠組みから詳細へ掘り下げたい | 一覧・概要は選ぶための要点、詳細は理解・判断する材料を置く | 全内容を一画面へ集めず、少量の関連情報を機械的に別ページへ分けることもしない |
| 説明文がなくても意味が分かる表示を好む | 名前・見出し・配置・関係で用途を伝え、使い方や語の意味を説明する常設文を減らす | 対象のMissionや状態の理由、判断材料は内容であって補足説明ではない。欠損状態や必要な注意、サンプル表示まで消さない |
| 文言は短く、対象を直接表したい | 「何かを切り替える」より対象名、日本語で不自然な抽象表現より内容を表す見出しを使う | ボタンの動作やscopeが曖昧になる場合は、必要な動詞・対象を残す |
| 同じ意味・同じ移動先の重複を減らしたい | 状態そのものを見出しにできるなら一般名と重ねず、名前から詳細へ移動できるなら同じ行に重複リンクや装飾矢印を足さない | 別の行動やリンクだと分からない場合には、必要な操作の手掛かりを残す |
| 一緒に見るが意味の異なる情報は、同列かつ別物として見たい | 関連する状況を独立した領域・見出し・間隔で並べる | 異なる件数や状態を一つの総合ラベルへ混ぜない。業務上の包含・重複関係は対象製品で定義する |
| 切替の入口と現在の階層を残したい | 上位のナビゲーションを維持し、選択中の対象の配下へローカル項目を階層表示する案を優先する | 多数の対象がある場合は見通しを再確認する。階層メニューを全UIで強制するものではない |
| 意味のない余白や操作専用行を減らしたい | 短い詳細も上寄せし、補助操作は関連する操作と同じ行へ収める | まとまりを伝える間隔とタップ領域は維持する。密度だけを最大化しない |
| スマートフォンのメニューは右側で扱いたい | 右上のハンバーガーと右側のパネルをそろえる。閉じるアイコンもパネル右上に置く | 右利きの利用者の好み。PCのナビゲーションまで右へ移す意味ではない |
| 明確な操作はアイコンを使い、表示を簡潔にしたい | メニューと閉じるは、意味が通るアイコンを使って関連行へ収める | アクセシブルな名前、開閉状態、タップ領域、閉じた後のfocusを確保する。未知の操作までアイコン化しない |
| 一覧の長文は抑え、詳細で全文を読みたい | 一覧の補助テキストを必要な行数で省略し、詳細は本文を読めるようにする | 一覧と詳細の要望を矛盾と扱わない。行数・省略対象は画面ごとに決める |

## 保守

新しい指摘のたびに、該当する既存行を更新する。同じ条件への古い好みを併記しない。文脈が違う場合は適用範囲・例外へ統合する。製品の個別修正から無関係な一般ルールを増やさず、次の設計判断に役立つ粒度へまとめる。配布先のコンパイル済みコピーを正本として直接更新しない。
